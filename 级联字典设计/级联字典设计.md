# 级联字典与计划类型级联设计

- 日期：2026-10-09
- 范围：本轮仅 **know-vue**（后端 + know-vue 管理页 + know-vue 计划表单接入），uniapp 下轮。
- 状态：设计待评审（评审通过后进入实现计划）

---

## 1. 背景与目标

现状问题：
- 「字典管理」（系统管理下）是**平铺**维护：字典类型 → 字典数据（标签/值/排序/状态）。
- 计划类型有两套且不一致：
  - 后端 `plan_type` 表（`type_name/type_code/icon/color/sort/status`），已有 6 条种子数据，但**无 CRUD 接口/页面**；
  - 前端计划表单里的「计划类型」是**写死的 `<a-select>`**，并未读取 `plan_type`。
- `plan_info.plan_type` 存单个 `type_code` 字符串。

目标：
1. 新增一套**通用「级联字典」**能力（类型 + 树形数据），与现有平铺字典并行、互不影响。
2. 系统管理下新增「级联字典」菜单，提供类型管理 + 树形数据维护。
3. 计划类型改为**级联选择**（可任意层级），把现有 6 个类型作为顶层种子数据接入。

---

## 2. 需求确认结论（8 问）

| # | 问题 | 结论 |
|---|------|------|
| 1 | 能力范围 | **A 通用级联字典**（计划类型是第一个使用场景） |
| 2 | 数据模型 | **A 新建独立一套**（`sys_cascade_dict_type` + `sys_cascade_dict_data`），与现有字典并行 |
| 3 | 数据项字段 | **A 基础字段 + icon/color** |
| 4 | 选择/存储语义 | **A 任意层级可选**，存所选节点编码，展示时前端用树解析完整路径 |
| 5 | 菜单位置 | **A 系统管理 → 级联字典** |
| 6 | 页面结构 | **A 两级式**：类型列表 →「级联数据」树形弹窗（复用行业树形表格交互） |
| 7 | 初始数据 | **A** 现有 6 个类型迁移为顶层，不预置下级 |
| 8 | 实现范围 | **A** 先做 know-vue，uniapp 下轮 |

补充确认：
- **菜单接入方式**：与行业菜单一致（SQL 迁移补菜单行），代码里同时加静态路由。
- **icon/color**：保留。

---

## 3. 关键设计取舍

- **独立 vs 扩展**：选择新建独立表。理由：隔离清晰，不影响既有平铺字典消费方；不做给通用字典加 `parent_id` 的侵入式改造。
- **级联选择值**：`plan_info.plan_type` 继续存**所选节点的 `value`（编码）**，不存路径，老数据零改动；层级展示由前端用树解析。
- **查询语义不变**：本轮不做「选父级含全部下级」，计划查询仍按精确编码过滤。

## 4. 后端设计

模块：`know-boot-system`（对齐现有 `SysDict` 域）。

### 4.1 数据表

**`sys_cascade_dict_type`（级联字典类型）**

| 列 | 类型 | 说明 |
|----|------|------|
| id | bigint PK auto | 主键 |
| type_name | varchar(100) | 类型名称 |
| type_code | varchar(100) | 类型编码，UNIQUE |
| status | tinyint | 状态(0停用/1启用) |
| remark | varchar(255) | 备注 |
| create_by / create_time | varchar(64) / bigint | 创建信息 |
| update_by / update_time | varchar(64) / bigint | 更新信息 |
| del_flag | tinyint | 逻辑删除（`@TableLogic`） |

**`sys_cascade_dict_data`（级联字典数据）**

| 列 | 类型 | 说明 |
|----|------|------|
| id | bigint PK auto | 主键 |
| dict_type_id | bigint | 所属级联字典类型 |
| parent_id | bigint | 父级（0=顶级） |
| name | varchar(100) | 显示名 |
| value | varchar(100) | 编码 |
| icon | varchar(100) | 图标 |
| color | varchar(20) | 颜色 |
| sort | int | 排序 |
| status | tinyint | 状态(0停用/1启用) |
| create_by / create_time | varchar(64) / bigint | 创建信息 |
| update_by / update_time | varchar(64) / bigint | 更新信息 |
| del_flag | tinyint | 逻辑删除 |

约束：`UNIQUE KEY (dict_type_id, value)`；`INDEX (dict_type_id, parent_id)`。

### 4.2 多租户
`CustomTenantLineHandler.IGNORE_TENANT_TABLES` 增加 `sys_cascade_dict_type`、`sys_cascade_dict_data`（系统级，不过滤租户，与 `sys_dict_type` 一致）。

### 4.3 建表与种子
新增 `SystemSchemaMigration`（对齐 `PlanSchemaMigration`/`BizSchemaMigration` 的 `tableExists` + `CREATE TABLE IF NOT EXISTS` 模式）：
- 建两张表；
- seed 级联字典类型 `plan_type`（名称「计划类型」）；
- seed 6 个顶层节点（value 沿用现有编码，保证老 `plan_info.plan_type` 可解析）：

| name | value | icon | color | sort |
|------|-------|------|-------|------|
| 生活习惯 | life | 🏃 | #67C23A | 1 |
| 认知提升 | cognition | 📚 | #409EFF | 2 |
| 工作技能 | skill | 💼 | #E6A23C | 3 |
| 项目 | project | 📦 | #909399 | 4 |
| 兴趣爱好 | hobby | 🎨 | #F56C6C | 5 |
| 学习 | study | 🎵 | #8E44AD | 6 |

> 老 `plan_type` 表**保留不动**。

### 4.4 实体 / Mapper
- 实体：`SysCascadeDictType`、`SysCascadeDictData`（`entity.tenant`，`@TableName` 指向新表）。
- Mapper：`SysCascadeDictTypeMapper`、`SysCascadeDictDataMapper`（`mapper.tenant`，extends `BaseMapper`）。

### 4.5 Service `ISysCascadeDictService` / impl
- 类型：`list`（按名称/编码/状态过滤）、`get`、`add`（type_code 唯一校验）、`update`、`delete`（**存在数据则拒绝**）。
- 数据：`tree`（按 typeCode/typeId，可选 status）、`list`、`add`（value 同类型唯一；父级须同类型且存在）、`update`（父级不可为自己/后代；value 唯一）、`delete`（**存在下级则拒绝**）。

### 4.6 Controller `SysCascadeDictController` → `/api/system/cascade-dict`
| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/type/list` | 类型列表（条件过滤） |
| GET | `/type/{id}` | 类型详情 |
| POST | `/type` | 新增类型 |
| PUT | `/type` | 修改类型 |
| DELETE | `/type/{id}` | 删除类型（有数据则拒绝） |
| GET | `/data/tree` | 树（`typeCode`/`typeId`/`status`） |
| GET | `/data/list` | 平铺列表 |
| POST | `/data` | 新增数据 |
| PUT | `/data` | 修改数据 |
| DELETE | `/data/{id}` | 删除数据（有下级则拒绝） |

### 4.7 菜单接入（与行业菜单一致）
- 静态路由：`router/routes/modules/system.ts` 增加子路由 `cascade-dict`（title「级联字典」）。
- DB 菜单：向 `sys_menu` 插入一条「级联字典」菜单行（父级=系统管理，path=`/system/cascade-dict`，menu_type=2），沿用现有迁移/脚本方式；SQL 迁移编号接续现有序列。实现时先查库确定空闲 id 与系统管理父级 id。

## 5. know-vue 前端设计

### 5.1 API `src/api/system/cascadeDict.ts`
- 类型：`CascadeDictType`；数据：`CascadeDictData`、`CascadeDictNode`（含 children）。
- 类型 CRUD、数据 CRUD、`getCascadeDictTree({ typeCode? | typeId?, status? })`。
- 便捷方法：`getPlanTypeTree()`（`typeCode='plan_type', status=1`）。

### 5.2 管理页 `src/views/system/cascadeDict.vue`（结构对齐 `system/dict.vue`）
- 搜索：名称 / 编码；类型表格：名称、编码、状态、备注、创建时间、操作（**级联数据** / 编辑 / 删除）；工具栏「新增」。
- 弹窗 A：类型表单（名称、编码、状态、备注）。
- 弹窗 B「级联数据」：树形表格，默认全展开；列：名称、编码、图标、颜色、排序、状态、操作（**新增下级** / 编辑 / 删除）；顶部「新增顶级」。
- 数据表单：父级（`a-tree-select`，可清空=顶级）、名称、编码、图标、颜色、排序、状态。
- 删除拦截：删除有下级的节点 / 有数据的类型 → 前端提示 + 后端兜底。

### 5.3 计划表单接入级联（4 处）
- `plan/info/index.vue`（查询 + 表单）
- `plan/template/info/index.vue`
- `plan/template/habit/index.vue`
- `plan/template/event/index.vue`

改为：
- 写死的 `<a-select>` → `<a-cascader>`（`change-on-select`，允许选任意层级）；
- 选项来自 `getPlanTypeTree()`；
- 新增通用小工具 `src/utils/cascadeDict.ts`：`buildCascaderOptions(tree)`（树 → 级联选项）与 `resolveCascadePath(tree, value)`（value → 完整路径用于展示）；
- `form.planType` 保存末位节点 value；列表/详情展示完整路径（如「工作 / 编程」）；
- 查询仍按精确编码过滤（不改查询语义）。

## 6. 兼容性
- 老 `plan_type` 表保留，不受影响。
- 老 `plan_info.plan_type` 值（life/cognition/skill/project/hobby/study）与新 seed 顶层 value 对齐，可正常解析展示。
- 现有平铺「字典管理」页面与消费方完全不受影响。

## 7. 边界与校验
- 类型编码（type_code）全局唯一。
- 数据编码（value）同类型内唯一。
- 父级不可为自己或自己的后代（环校验）。
- 删除有下级的节点 → 拒绝；删除有数据的类型 → 拒绝。
- 消费端树默认只返回启用（status=1）节点；管理页取全部。
