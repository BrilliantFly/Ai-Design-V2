# 02 · 设计目标与原则

> 文档版本：V1.0
> 前置文档：[01-现状分析.md](./01-现状分析.md)

---

## 一、优化目标

### 目标 1：首屏聚焦，降低信息密度

将首屏区块数从 5 个压缩到 3 个核心区块，让用户一屏内看清「我是谁 → 我有什么待办 → 我能做什么」。

**可量化指标**：
- 首屏可见区块数 ≤ 3（不含底部导航）
- 首屏滚动深度 ≤ 设备高度的 1.2 倍

---

### 目标 2：建立统一的设计 Token 体系

将间距、圆角、字号、阴影、色彩全部抽象为 CSS 变量，页面不再出现硬编码数值。

**可量化指标**：
- 硬编码色值占比 ≤ 5%（仅 emoji 等不可控元素）
- 间距取值来自统一 scale（4 / 8 / 12 / 16 / 20 / 24 / 32rpx）
- 圆角取值来自统一 scale（sm / md / lg / xl / pill）

---

### 目标 3：建立清晰的视觉层级

通过字号、字重、色彩对比度、卡片层级 4 个维度，让用户 3 秒内识别页面重点。

**可量化指标**：
- 页面主标题与正文对比度 ≥ 1.5 倍字号差
- 主卡片与次卡片可通过阴影/圆角/背景区分
- 语义色（成功/警告/危险）仅用于状态指示，不用于装饰

---

### 目标 4：统一图标语言

全页统一使用 SVG 图标风格，淘汰 emoji 作为功能图标（emoji 仅保留在装饰性位置如问候语）。

**可量化指标**：
- 功能图标 SVG 化覆盖率 ≥ 95%
- 图标尺寸统一为 3 档（sm 32rpx / md 40rpx / lg 56rpx）

---

### 目标 5：强化主题适配

首页所有色值走主题变量，20 套主题下均保持良好对比度与视觉一致性。

**可量化指标**：
- 浅色主题文字对比度 ≥ 4.5:1（WCAG AA）
- 深色主题文字对比度 ≥ 4.5:1
- 切换主题无硬编码色块残留

---

### 目标 6：保留全部现有功能入口

样式优化不删减任何功能入口，仅调整视觉呈现与位置。所有现有跳转路径、交互逻辑保持不变。

---

## 二、设计原则

### 原则 1：克制用色

- **全页主渐变色仅 1 处**：Hero 顶栏使用主题主色渐变。
- **功能区块不使用彩色渐变背景**，统一使用表面色 + 主题色点缀。
- **语义色仅用于状态**：红（告警/危险）、黄（警告/待办）、绿（成功/在线）、蓝（信息/链接）。
- 推荐卡片缩略图的多色渐变改为「统一浅底 + 主题色图标」或「单色系渐变」。

---

### 原则 2：呼吸感优先

- 区块间距统一为 `32rpx`（大区块）或 `24rpx`（小区块），不再出现 `14rpx`、`18rpx` 等碎值。
- 卡片内边距统一为 `24rpx`，小卡片统一为 `16rpx`。
- 宫格间距统一为 `16rpx`，行距与列距一致。
- 每个区块标题与内容之间保留 `16rpx` 固定间距。

---

### 原则 3：层级分明

- **L1 页面主标题**：Hero 问候语，`36rpx / 700`，主题对比色。
- **L2 区块标题**：`28rpx / 600`，主文字色。
- **L3 卡片标题**：`24rpx / 600`，主文字色。
- **L4 正文/描述**：`22rpx / 400`，次要文字色。
- **L5 辅助/标签**：`18rpx / 400`，三级文字色。

数字类信息（待办数、设备数）使用 `40rpx / 700`，但需搭配单位文字形成视觉组。

---

### 原则 4：卡片分层

将卡片分为 3 个层级，通过阴影与背景区分：

| 层级 | 用途 | 样式 |
|------|------|------|
| 主卡片 | 今日概要、核心数据 | 表面色 + `--shadow-md` + 圆角 `28rpx` |
| 次卡片 | 工具、推荐 | 表面色 + `--shadow-sm` + 圆角 `24rpx` |
| 容器 | 快捷宫格外壳 | 表面软色 + 无边框 + 圆角 `28rpx` |

取消所有卡片的 `2rpx solid border`，改用阴影区分边界；在深色主题下边框可保留但颜色取自 `--color-border`。

---

### 原则 5：图标统一

- 功能图标统一使用 SVG，颜色取自主题主色或语义色。
- 图标背景统一使用 `--color-primary-soft`（浅紫底），不再为每个功能分配不同渐变色。
- 图标圆角统一为 `16rpx`（方形图标）或 `50%`（圆形头像）。
- 「更多」「箭头」等符号图标统一使用 SVG chevron，淘汰 `›`、`•••`。

---

### 原则 6：动效克制

- 仅在「入场」和「点击反馈」两类场景使用动效。
- 入场动效采用淡入上移，总时长 ≤ `400ms`，错峰间隔 `80ms`。
- 点击反馈采用 `scale(0.97)` + 背景色微变，时长 `150ms`。
- 轮播自动播放间隔延长至 `5000ms`，避免干扰阅读。

---

### 原则 7：功能零删减

- 所有现有跳转路径（`goLink`、`goMore`、`handleQuickTap` 等）保持不变。
- 所有现有 API 调用（`getHomeMenu`、`getHomeConfig`、`getTodayStats` 等）保持不变。
- 所有现有数据结构（`quickTiles`、`recommendTiles`、`dashboardTools`、`utilityChips`）保持不变。
- 仅调整 template 结构层级与 style 表现。

---

## 三、非目标（明确不做）

1. **不新增功能模块**：不新增 AI 助手、天气、步数等新功能。
2. **不改动接口数据结构**：不要求后端新增字段或调整返回。
3. **不改动底部导航 Tab 配置**：Tab 项与跳转路径保持现状（语义问题在方案中给出建议但不强制改）。
4. **不引入新的 UI 库**：继续使用现有 uni-app 组件 + uView，不引入 vant、colorUI 等。
5. **不做骨架屏改造**：加载态保持现有空白渲染方式，不引入骨架屏组件。
