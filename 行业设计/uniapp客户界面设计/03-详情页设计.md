# 03 - 详情页设计（客户详情 + 跟进）

## 1. 客户详情页 `pages/customer/detail`（新增）

> 数据：`GET /api/biz/customer/{id}` → `{ ...bizCustomer, profile, company, industries, industryIds }`
> 页面滚动浏览，一级区域使用可折叠卡片（默认展开第一个），保证**合理固定高度**（历史约束：详情除非全屏，合理固定高度）。

### 1.1 页面结构（线框）

```
┌───────────────────────────────────────┐
│ ← 客户详情                     [编辑]   │  ← navbar，右上角"编辑"（中文）
```

> **视觉规范**（详情见 [05 文档 §4.5](./05-组件与交互规范.md#45-主题与样式欢迎语视觉基准)）：头部卡为 **hero 渐变页头**（`--gradient-primary` + 装饰圆 `::before/deco-ring`，头像白字 `--color-btn-text` + inset 光环，次级文字 `--color-btn-text` opacity 0.78，App 端 `padding-top += var(--status-bar-height)`）；区段卡片 `--color-surface` + `--shadow-sm`，二级小节 `--color-surface-soft`；行业 Tag 选中 `--color-primary` + `--color-btn-text`、未选中 `--color-primary-soft` + `--color-primary` 文字；跟进时间线时间戳 `--color-text-tertiary`、内容 `--color-text`。全量使用主题变量，20 套主题自动换肤（含深色主题）。

### 1.2 区段折叠约定

| 区段 | 默认状态 | 数据源 |
|------|----------|--------|
| 客户个人资料（基础认识/详细认识） | 展开 | bizCustomer |
| 基础情况 | 折叠 | bizCustomer |
| 业务情况 | 折叠 | bizCustomer |
| 客户企业与行业情况 | 折叠 | company + industries |
| 动态信息 / 价值信息 / 如何把握 | 折叠 | profile |
| 跟进记录 | 展开（有数据时） | followup/list |

- 折叠动画：uni-collapse / uni-transition 淡入淡出均为可选；实现推荐 `uni-collapse` 或自定义 `v-if + transform`。
- 区段内二级区域以"小节标题 + 分组边框"呈现（视觉对齐 PC 端 `SubSection`）。

### 1.3 字段展示明细（详情项 = label + value）

- 空值统一显示 `--`（灰色）。
- **赚钱方式 / 社会阶层**：逗号串 `split(',')` 后渲染为小标签（可点选样式，选中态仅为展示）。
- **行业情况**：`industries[]` 渲染为 Tag 行（`industryName`），无则"未关联行业"，旁挂 [关联行业] 按钮（可选，弹 IndustryPicker → `POST /api/biz/customer/{id}/industries`）。
- **手机号/邮箱**：后端已脱敏，直接展示；长按 `uni.setClipboardData` 复制（可选增强）。

### 1.4 头部操作

| 操作 | 行为 |
|------|------|
| [编辑] | → `form?mode=edit&id={id}&from=detail` |
| [添加跟进] | → `followup?customerId={id}` |
| [关联行业]（可选） | 底部弹层 IndustryPicker（见 05 组件规范），确认后全量覆盖关联 |

## 2. 跟进记录 `pages/customer/followup（改造）`

> 现有 `followup.vue` 为静态占位，改造为"列表 + 新增"两态页面。

### 2.1 新增态（默认，带 `customerId` 参数）

```
┌───────────────────────────────────────┐
│ ← 添加跟进                             │
├───────────────────────────────────────┤
│ 跟进内容 *                            │
│ ┌───────────────────────────────────┐│
│ │ 多行文本 textarea，placeholder:     ││
│ │ 请输入跟进内容(含沟通要点、结果)     ││
│ └───────────────────────────────────┘│
│ 跟进方式         [电话 ▾]             │  ← 选择器：电话/微信/拜访/邮件/其他（已确认扩展）
│ 下次跟进时间     [2026-09-28 ▾]       │  ← uni-datetime-picker（可空，已确认扩展）
│ 备注（可选）                          │
│ ┌───────────────────────────────────┐│
│ │                                    ││
│ └───────────────────────────────────┘│
├───────────────────────────────────────┤
│           [ 保存 ]                    │  ← 中文主按钮
└───────────────────────────────────────┘
```

- 提交：`POST /api/biz/customer/followup { customerId, content, followType, nextTime, remark }`
- 成功 → toast"保存成功" → `navigateBack()`（详情页刷新跟进时间线）。
- 校验：`content` 非空（uni-forms 规则）。
- 字段来源：`followType / nextTime` 为**已确认扩展字段**（README 未决事项 3 闭环，后端 `BizCustomerFollowup` 表补充列）。

### 2.2 列表态（同页底部"历史记录"）

```
│ 历史记录（最近 10 条）
│  ┌ 2026-09-20 10:30  电话            │
│  │ 确认预算与决策人，下周出方案         │
│  │ 📌 下次跟进：2026-09-28           │  ← nextTime 展示（可空时省略）
│  ├ 2026-09-15 14:02  微信             │
│  │ 已发送产品资料 V2                  │
│  └ [查看全部 →]                       │
```

- 数据：`GET /api/biz/customer/followup/list?customerId={id}`（时间倒序）；详情页与跟进页共用该接口。
- 时间线条目结构：`{ content, followType, followTime, nextTime, remark }`；`nextTime` 非空时以弱化样式展示"下次跟进：yyyy-MM-dd"。
