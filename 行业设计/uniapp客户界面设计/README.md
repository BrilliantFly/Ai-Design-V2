## 1. 背景与问题诊断

用户反馈"现在没有 uniapp 客户界面显示"，经排查 `E:\Ai-Project\Ai-Front\know-uniapp` 现状：

| 问题 | 现状 | 根因 |
|------|------|------|
| 客户数据调不通 | 列表/统计接口返回空或 HTML | `src/api/customer.ts` 请求 `/customer/*` 路径无 `api` 前缀，**未被 vite 代理**（`vite.config.ts` 只代理 `/api`、`/adminapi`）→ 打到 dev server 自身 → `isHtmlResponse` 兜底为空 |
| 无新增客户入口 | FAB "+" 仅弹 toast"新增客户功能待接入" | 没有客户新增/编辑页面 `pages/customer/form` |
| 无客户详情页 | 点击客户直接跳 `/pages/customer/followup` | 没有 `pages/customer/detail` 页面 |
| 详情/跟进占位 | `followup.vue` 是静态占位（textarea + 提交按钮无逻辑） | 未接入任何 API |
| 数据模型过时 | `CustomerInfo/CustomerForm` 类型缺 10+ 新字段（外貌/性格/衣食住行/赚钱方式/社会阶层/生活技能等） | 后端 `BizCustomer` 已扩展，前端类型未同步 |
| 首页入口已存在 | 首页快捷入口 `quick-customer` → `/pages/customer/info` | 入口在，但页面侧数据断、页面不全 |

## 2. 设计目标

1. **打通数据通道**：客户 API 统一迁移到 `/api/biz/customer/*`（复用现有 `/api` → 8082 代理），与 PC 端（know-vue `src/views/biz/customer`）同一套后端接口、同一字段模型。
2. **补齐页面闭环**：列表 → 详情 → 新增/编辑 → 跟进，五页闭环，覆盖客户 360° 画像（基础认识/详细认识/企业/行业/需求/动态/价值/如何把握）。
3. **对齐 V3 层级模型**：表单与详情同构，字段层级镜像 PC 端 `sections.ts` 区域树，移动端以"可折叠卡片"呈现。
4. **继承既有交互规范**：按钮中文、placeholder 带括号及内容、控件通栏宽度、详情区段合理固定高度（页面滚动 + 折叠）、操作项文字不换行。
5. **视觉对齐"欢迎语"**：全页视觉沿首页 hero 欢迎语风格（渐变页头 + 半透明装饰圆 + 白色文字/毛玻璃头像 + 图标浮层），列表/详情强样式区沿用同款渐变主色块，表单区段卡片化。
6. **适配 20 套视觉主题**：只使用 `themes.scss` / `THEME_COLORS` 定义的主题变量（`--color-*` / `--shadow-*` / `--gradient-primary`），切换主题（H5 `data-theme`、小程序/App 内联变量）后客户界面全量跟随，无写死色值。

## 3. 关键设计决策

| # | 决策 | 说明 |
|---|------|------|
| D1 | API 切换 `/customer/*` → `/api/biz/customer/*` | `api/customer.ts` 改用标准 `request`（带 `api` 前缀）+ 明确 `baseUrl`；删除 `customerRequest` 独立实例 |
| D2 | 数组字段约定 | 表单层 `earningWay/socialClass/industryIds` 用**数组**；提交层 join 为逗号串（`industryIds` 保持数组走 DTO）；详情回填 split 拆数组（PC 端已验证此模式） |
| D3 | 页面路由扩展 | 新增 `pages/customer/detail`、`pages/customer/form`；`info` 保留为列表页（标题改"客户管理"）；`followup` 改造接真实 API |
| D4 | 表单为整页（非弹层） | 移动端新增/编辑天然整页，无"弹窗全屏按钮"需求；PC 端弹窗全屏约束不适用，但**详情页区段折叠**保证合理高度 |
| D5 | 行业多选数据源 | `GET /api/biz/industry/page`（同 biz 模块，`del_flag=0`）驱动 `IndustryPicker`，与 PC 端 `IndustrySelect` 同源 |
| D6 | 企业情况区段常显 | ~~随客户类型显隐~~ → **已修订**：客户类型语义确认为 PC 端 `1 普通客户 / 2 重点客户`（非"个人/企业"），故"客户企业与行业情况"区段**始终显示**，不再随类型隐藏；`company.*` 字段可整体留空，"未关联企业"内联提示兜底 |
| D7 | 登录拦截 | 新增页面 meta `auth: true`，沿用 `router` 登录拦截（未登录跳登录页并记录回跳） |
| D8 | **菜单配置入计划** | 菜单为后台动态下发（`sys_menu_config` 表 + `/system/menu/config` 接口，CRUD 已存在），**把"客户管理"菜单配置落库作为本计划必配项**（`menuType=2` 首页菜单，`menuCode=customer`，`path=/pages/customer/info`）。**底部 tab 不配置（已确认）**，客户入口 = 首页菜单 + 列表页 FAB。配置后 uniapp 无需发版即显示入口。详见 [01-页面导航与流程.md](./01-页面导航与流程.md#6-动态菜单配置后台维护) |
| D9 | **视觉基准 = 首页"欢迎语"风格** | 视觉基准采样 `src/pages/index/index.vue` 的 `hero-bar`（渐变页头 `linear-gradient(135deg, --color-primary, --color-minor)`、`::before/::after` 大装饰圆、`deco-ring` 圆环、`deco-dot` 点阵、白色 `hero-avatar` 圆形头像含 inset 光环、`hero-name/hero-sub` 白字双层、`hero-icon` 毛玻璃浮层）。列表/详情页强样式区复用同款 hero 视觉语言；表单区段用卡片 + 主题变量。详见 [05-组件与交互规范.md §4.5](./05-组件与交互规范.md#45-主题与样式欢迎语视觉基准) |
| D10 | **20 套视觉主题双通道适配** | H5 端由 `html[data-theme]` + `themes.scss` 生效；小程序/App 端由 `stores/theme.ts` `themeInlineVars` getter 注入内联变量（服务端配色经 `getDecorate` 覆盖 `primary/minor/btn-text`）。客户界面一律引用主题变量，**禁止写死色值/阴影/渐变**；hero 头部文字用 `--color-btn-text` 不假设白色（macaron/milky/neon 为深色文字），玻璃 shadow 用 `--shadow-*`（glass 主题为 none）。详见 [05-组件与交互规范.md §4.5](./05-组件与交互规范.md#45-主题与样式欢迎语视觉基准) |
