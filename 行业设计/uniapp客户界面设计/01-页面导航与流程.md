## 3. 用户流程

### 3.1 客户建档（新增）主流程

```
首页快捷入口
  └─ 客户列表 /pages/customer/info
       └─ FAB "+" → /pages/customer/form?mode=create
            ├─ 填写 客户个人资料（基础认识：基础信息/个人信息/职业信息/圈子）
            │            （详细认识：家庭状态/教育背景/生活技能）
            ├─ 客户类型=企业(2) → 展开"企业情况"（company.*）
            ├─ 选择"所属行业(多选)" → IndustryPicker（GET /api/biz/industry/page）
            ├─ 需求/业务情况（demand*）
            ├─ 动态信息/价值信息/如何把握（profile.*）
            ├─ [保存] → POST /api/biz/customer
            └─ 成功 → toast"保存成功" → 返回列表刷新（或直达详情）
```

### 3.2 查看与维护流程

```
客户列表
  └─ 点击卡片 → /pages/customer/detail?id={id}
       ├─ 区段折叠查看画像（基础认识/详细认识/企业/行业/需求/动态/价值/如何把握）
       ├─ [编辑] → /pages/customer/form?mode=edit&id={id} → PUT /api/biz/customer → 返回详情刷新
       ├─ 跟进时间线（GET /api/biz/customer/followup/list?customerId=）
       └─ [添加跟进] → /pages/customer/followup?customerId={id} → POST .../followup → 返回刷新
```

### 3.3 登录拦截

- 以上全部页面 `meta.auth: true`，未登录跳 `/pages/login/login`，登录成功后回跳原页面（沿用现有 `requireLogin` 机制）。

## 4. 页面间参数约定

| 参数 | 页面 | 含义 |
|------|------|------|
| `mode` | form | `create` / `edit` |
| `id` | detail / form | 客户主键（form 编辑态必传） |
| `customerId` | followup | 客户主键（写跟进记录时回带） |
| `from` | form | `list` / `detail`（保存后返回目标，默认列表） |

## 6. 动态菜单配置（后台维护）—— 计划项

### 6.1 机制说明（已确认可用）

菜单是**后台动态下发**的，uniapp 客户端无需改代码即可让"客户管理"出现在首页/底部导航：

```
后端 sys_menu_config 表（SysMenuConfig 实体，控制器 SysMenuConfigController 已提供完整 CRUD）
  ├─ GET /api/system/menu/config/home          → store.menuConfig.home   → 首页菜单
  ├─ GET /api/system/menu/config/home/user     → 同上（按权限过滤）
  ├─ GET /api/system/menu/config/tabbar        → store.menuConfig.tabbar → PremiumBottomNav
  └─ GET /api/system/menu/config/tabbar/user   → 同上（按权限过滤）
        ↓
uniapp App.vue → stores/app.ts loadPublicMenuConfig() / loadUserMenuConfig()
        ↓
首页九宫格 / 快捷入口 / 底部导航渲染
```

- 菜单类型：`menuType` 1=tabBar / 2=首页 / 3=侧边栏
- 渲染类型：`renderType` 1=动态（默认）/ 2=表单 / 3=自定义
- 权限控制：`permissionCode` 绑定角色权限；不绑权限的项走公开接口（未登录也可见）
- 前端菜单图标映射：`menuCode` 含 `customer`/`crm` 或 `path` 含 `/pages/customer/` → 自动归入 customer fallbackKey（svg 头像图标 已内置）

### 6.2 计划配置项（后台菜单管理新增，或开发期由 SQL/初始化脚本落库）

**① 首页菜单（九宫格/快捷入口）—— 必配，替代前端写死的 `quick-customer`：**

| 字段 | 值 | 说明 |
|------|-----|------|
| menuName | 客户管理 | 展示名 |
| menuCode | customer | 前端 fallbackKey 识别 |
| menuType | 2（首页） | 渲染到首页菜单区 |
| path | /pages/customer/info | 客户列表页路由 |
| icon | 后端图标库编码（如 customer.svg 对应值） | 首页图标 |
| selectedIcon | 同 icon | 选中态图标 |
| sort | 按现有菜单序号排 | 顺序 |
| isShow | 1 | 显示 |
| isBig | 1 | 是否大图标（九宫格） |
| renderType | 1（动态） | 默认动态渲染 |

**② 底部导航 tab —— 不配置（已确认）：**

> 用户确认不启用底部 tab。底部导航维持现有 5 项（工作台/小记/新建/知识库/我的）不动，客户仅通过首页菜单 + 列表页 FAB 进入。

### 6.3 配置 + 验证步骤（实施计划）

1. 后台菜单管理 → 新增"客户管理"菜单配置（sys_menu_config，字段见 6.2）→ 保存。
2. （可选）需要权限控制时绑定 permissionCode 到角色。
3. uniapp 端重新加载/冷启动 → store 自动拉取最新菜单（无需发版/改码）。
4. 验证：首页出现"客户管理"入口 → 点击跳转 `/pages/customer/info` → 列表正常显示（依赖 06 文档 API 迁移完成）。

> 结论：**把"客户管理"菜单配置落库到 sys_menu_config 是本次计划的一部分**——即使首页已有前端预设入口，也应同步改为后台配置项统一管理，避免双处维护。
