# 06 - 接口与数据模型设计

## 1. 关键结论：API 迁移

现有 `src/api/customer.ts` 通过独立 `customerRequest` 实例请求 **`/customer/*`** 路径：

```
原因：customerRequestOptions.baseUrl = ''（dev）、urlPrefix = '' → 最终 URL = /customer/detail?id=…
      vite 代理仅覆盖 /api、/adminapi → /customer 请求落到 dev server(index.html) → isHtmlResponse 兜底空数据
```

**设计决策 D1：迁移到 `/api/biz/customer/*`，与 PC 端同一后端接口。**

- 方式 A（推荐）：`api/customer.ts` 改用标准 `request`（`@/utils/request`，baseUrl + urlPrefix `api`），路径写 `/biz/customer/...` → 最终 `/api/biz/customer/...` → vite `/api` 代理 → 8082。
- 方式 B：保留独立 `customerRequest` 但改 `baseUrl = appConfig.baseUrl + 'api'`（等价，不推荐双通道）。
- 生产（H5/小程序/App）：`baseUrl` 由 `VITE_APP_BASE_URL` 决定（App 端兜底 `http://101.37.83.88:9191`，nginx 同域反代 `/api/biz/**` → biz 服务），与现有 plan/news 等模块一致。

| 表单 key | BizCustomer 列 | 详情展示 |
|----------|---------------|----------|
| name/gender/age/phone/email/address | 同名 | 头部卡片 |
| regionCode | regionCode | 基础情况区 |
| appearance/personality/lifestyle/hobby | 同名 | 个人信息 |
| occupation/position/earningWay | 同名 | 职业信息（多选→Tag） |
| socialClass/socialCircle | 同名 | 圈子（社会阶层→Tag） |
| maritalStatus/familySituation/familyAddress | 同名 | 家庭状态 |
| education(+educationRaw) / valuesText | 同名 | 教育背景 |

| customerType/source/status | 同名 | 基础情况 |

> 数组字段前后端约定：
> - `earningWay`/`socialClass`：DB TEXT 逗号串；表单层数组 ↔ 提交/回填 `join/split(',')`
> - `industryIds`：数组入参（DTO 已有 `List<Long> industryIds`）

## 5. 关键坑位清单（开发期注意，沿自 PC 端实测）

1. **数组与字符串**：多选字段 model 必须初始化为数组，否则 `join is not a function`（PC 端踩过坑）。
2. **company 空值**：后端 `sanitizeBlankFields` 会把空串转 null，`establishedDate` 空串不再报错；前端空对象 company 可不传。
3. **companyId 复用**：编辑保存不重建 company（后端已回写 companyId）。
4. **详情数据完整性**：详情必须调 `GET /{id}` 全量接口，不可复用列表 record（列表 company/industries 为 null，PC 端踩过坑）。
5. **脱敏**：phone/email 后端返回脱敏串，前端不再自行处理；**编辑表单回填的是脱敏值**（若不支持明文回显，需后端提供"编辑回填专用"接口或约定 phone 密文回传，**列入评审项**）。
6. **登录 token**：switch 到标准 `request` 后沿用 `utils/request` 的 token 注入（header.token），无需自定义拦截器；`retryCount=2` 需在标准通道确认是否保留。
7. **跟进扩展列（已确认）**：`biz_customer_followup` 需补 `follow_type`（电话/微信/拜访/邮件/其他）与 `next_time`（下次跟进时间）两列，列表接口返回新字段；老数据两列可空，前端时间线对空 `nextTime` 省略显示。
