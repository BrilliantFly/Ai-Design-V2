## 2. 流程 A：管理员配置（一次性）

```
管理员 → know-vue 设置页
  1. 填写 baseUrl / Basic 用户名 / 密码 / 默认模型
  2. 点击「测试连通」
     → POST /api/ai/config/test  (参数不落库)
     → 后端构造临时 OpenCodeClient
     → GET {baseUrl}/provider
     → 返回 { connected: true, freeModelCount: 14 }
  3. 点击「保存」
     → POST /api/ai/config  (密码 AES 加密落库, id=1 upsert)
     → GET /api/ai/models/free 刷新模型下拉
```

## 3. 流程 B：用户打开对话

```
用户点击悬浮球
  → know-vue: 打开 a-drawer  /  know-uniapp: 弹出 uni-popup
  → 检查本地 sessionId
     ├─ 无 → POST /api/ai/session { title: "AI对话" }
     │       → 后端 POST {baseUrl}/session 获取 opencodeSid
     │       → 落库 ai_chat_session
     │       → 返回 { sessionId, opencodeSid }
     └─ 有 → GET /api/ai/session/{id} 拉取历史消息渲染
```

## 4. 流程 C：发送一条消息（流式，核心）

### 4.1 前端发起

```
Vue/uniapp → POST /api/ai/chat  (Accept: text/event-stream)
  body: { sessionId: 123, content: "你好", model: "opencode/space-bunny-free" }
```

### 4.2 后端处理（know-boot-ai）

```
AiChatService.streamChat():
  ① 写入 ai_chat_message (role=user, content="你好", status=done)
  ② 构造 ChatRequest { model, parts: [{type:"text", text:"你好"}] }
  ③ OpenCodeClient.promptAsync(opencodeSid, req)
     → POST {baseUrl}/session/:id/prompt_async  → 204
  ④ 返回 SseEmitter(120s)
  ⑤ 后台订阅 GET {baseUrl}/event (WebClient)
```

### 4.3 opencode → 后端 → 前端 的事件转发

```
opencode /event 流:
  message.updated          (user 消息)        → 后端忽略（已自己落库）
  message.part.updated     (user text)        → 忽略
  message.updated          (assistant 占位)   → 忽略
  session.status {busy}                       → 忽略
  message.part.updated     (step-start)       → 忽略
  message.part.delta       {field:"text", delta:"你"}  ★
      → 后端 emitter.send({ type:"delta", text:"你" })
      → 前端 messages.at(-1).content += "你"
  message.part.delta       {delta:"好"}       ★ → 转发
  ...
  message.part.updated     (最终 text part)  → 忽略
  message.updated          (assistant 最终 cost)→ 忽略
  session.status {idle}                       ★
      → 后端拼接完整 assistant 文本
      → 写入 ai_chat_message (role=assistant, status=done)
      → emitter.send({ type:"done", messageId: 456 })
      → emitter.complete()
```

### 4.4 前端渲染

```
fetch reader loop:
  解析 SSE 帧 data: {...}
  type=delta → 追加到当前 assistant 气泡（打字机效果）
  type=done  → 气泡状态置 done，隐藏「停止」按钮
```

## 5. 流程 D：非流式降级（App / 小程序）

```
uniapp → POST /api/ai/chat  (body 增加 stream:false)
  → 后端检测 stream=false
  → 改走 POST {baseUrl}/session/:id/message (阻塞)
  → 等待完整返回 { info, parts:[{type:"text", text:"..."}] }
  → 落库 ai_chat_message (assistant, status=done)
  → 返回 AjaxResult { data: { content: "..." } }
  → 前端一次性渲染完整气泡（无打字机）
```

---

## 6. 流程 E：中断生成

```
用户点击「停止」
  → 前端 AbortController.abort() (H5)
  → POST /api/ai/chat/abort { sessionId }
  → 后端 POST {baseUrl}/session/:id/abort
  → opencode 停止生成
  → 已收到的 delta 拼接落库 (assistant, status=done, content=部分文本)
  → emitter.complete()
```

---

## 7. 流程 F：会话历史与清空

```
查看历史:
  GET /api/ai/session/{id}
  → 返回 { session, messages: [...] }

清空当前会话:
  DELETE /api/ai/session/{id}
  → 后端 DELETE {baseUrl}/session/:id
  → 逻辑删除 ai_chat_session + ai_chat_message (del_flag=2)
  → 前端清空 messages，重置 sessionId
```

---

## 8. 数据一致性说明

| 数据位置 | 内容 | 用途 |
|---------|------|------|
| opencode 侧 | session + message（可能留存） | 模型记忆上下文 |
| 本地 MySQL | `ai_chat_session` + `ai_chat_message` | 业务侧历史、审计、分用户 |

> **以本地为主**：每次打开会话先 `GET /api/ai/session/{id}`（本地）渲染历史；发送时后端把用户消息本地落库后再转发 opencode。即使 opencode 重启丢会话，本地历史仍可展示（续聊时若 opencode 报会话不存在，后端自动 `POST /session` 重建并更新 `opencode_sid`）。

## 10. 异常路径

| 触发 | 后端动作 | 前端表现 |
|------|---------|---------|
| opencode 不可达 | `promptAsync` 抛 ConnectException | SSE 推 `{type:"error", msg:"AI 服务不可用"}` |
| opencode 会话不存在（404） | 自动 `POST /session` 重建，更新本地 `opencode_sid`，重试一次 | 无感（透明续聊） |
| 流式超 120s | `SseEmitter.onTimeout` | 气泡标红「超时」 |
| 用户中断 | `POST /session/:id/abort` | 已生成部分保留 |
| 并发会话超限（如 >10） | 拒绝 `POST /api/ai/session` | 提示「当前 AI 助手繁忙」 |
