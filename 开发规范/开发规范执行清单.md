## 1. 任务前（分析与设计）

- [ ] **明确端类型**：判定是 `uniapp（移动端）`、`know-vue（管理端）` 还是 `knowboot（后端）`，对应查阅对应规范文档。
- [ ] **查阅现有模式**：优先参考同业务域已有页面/接口（如 `views/biz/*`、`views/knowledge/*`、`api/biz/*`、`know-boot-biz`）复用模式，而不是全新设计。
- [ ] **评估公共能力**：如涉及级联字典、字段配置化（`sections.ts + FieldItem.vue + MatrixTable`）、SchemaMigration、主题等，优先遵循后端/后台相关章节。
- [ ] **列出影响范围**：前端页面、组件、API、路由、Store、后端 Controller/Service/Mapper/Entity、DB 变更等。

## 2. 后端（knowboot）开发核对

> 规范：`03-后端(knowboot)开发规范.md`

### 2.1 模块与包结构
- [ ] **选定模块**：确认所属模块（`know-boot-common/api/base/system/biz/plan/camera/knowledge/accumulate/start/standalone/microservice`），避免跨模块随意新增类。
- [ ] **包结构一致**：按 `controller/service/service.impl/mapper/entity/dto/vo/convert/config/enums/utils` 分层，包名 `com.know.knowboot.*`。
- [ ] **基类复用**：Entity 是否继承 `BaseEntity`（或符合项目现有基类约定）；Mapper 是否继承 `BaseMapper<*>`；Service 使用 `IService<*> + ServiceImpl<*,*>`。

### 2.2 数据库与实体
- [ ] **表前缀正确**：表名遵循 `sys_`、`biz_`、`plan_`、`kn_` 等实际前缀语义（按业务域选择）。
- [ ] **通用字段**：`id`、`create_time`、`update_time`、`del_flag`、`tenant_id` 等字段处理是否符合现有实体（注意 `id` 类型/生成策略差异：String+Date 与 Long+Long 并存）。
- [ ] **逻辑删除**：使用 MyBatis-Plus 逻辑删除（`@TableLogic`、`del_flag`）而非物理删除。
- [ ] **字段命名**：实体字段驼峰，表字段下划线；必要时使用 `@TableField` 明确映射。
- [ ] **租户**：如涉及租户隔离，确认是否走 `CustomTenantLineHandler` 及 `tenant_id` 处理。

### 2.3 接口与响应
- [ ] **RESTful**：Controller 路径统一（`/api/...` 前缀与项目约定一致）、动词语义清晰（GET/POST/PUT/DELETE）。
- [ ] **统一响应**：返回 `AjaxResult` 或 `Result`（项目中两种并存，**沿用所在模块现有风格**，不要混用）。
- [ ] **参数校验**：使用 `@Valid/@Validated`，必要时补充校验分组。
- [ ] **DTO→VO 转换**：使用已有 `convert` 工具或 `BeanUtil`，避免在 Controller/Service 直接手写大段字段映射。
- [ ] **分页**：使用 MyBatis-Plus 分页（Page + IPage）及项目通用分页参数封装。

### 2.4 数据访问
- [ ] **Mapper 写法**：优先 BaseMapper 方法，复杂查询用 `LambdaQueryWrapper`/`QueryWrapper`，必要时 XML 放在 `mapper/xml` 对应位置。
- [ ] **事务**：写操作添加 `@Transactional(rollbackFor = Exception.class)`（ServiceImpl 层为主）。
- [ ] **SQL 安全**：避免直接拼接 SQL，使用 MP 构造器或预编译。

### 2.5 字典、级联与迁移
- [ ] **字典**：如需字典项，优先复用 `sys_dict_type/sys_dict_data` 约定。
- [ ] **级联字典**：涉及级联（如 `industry_type`、`plan_type`）时使用 `sys_cascade_dict_type/sys_cascade_dict_data` 结构及现有 seed 方式。
- [ ] **SchemaMigration**：**新增字段/表**时优先通过 `SystemSchemaMigration` 或 `BizSchemaMigration` 的 `ensureColumnExists/ensureTableExists/seed*` 方法实现（不要只手动改 SQL 文件）。
- [ ] **数据初始化**：必要初始化数据走对应 `seed*` 方法，保持幂等。

### 2.6 配置与部署相关
- [ ] **配置文件**：按 profile 区分（`application-dev.yml`、`application-prod.yml` 等），端口 `8082`、Redis `16379` 等按环境正确配置。
- [ ] **异常处理**：沿用 `GlobalExceptionHandler` 处理业务异常/参数校验异常。
- [ ] **日志**：关键业务打印必要日志，避免敏感信息泄露。

## 3. 管理端（know-vue）开发核对

> 规范：`02-管理端(know-vue)开发规范.md`

### 3.1 工程结构与入口
- [ ] **目录规范**：页面放 `src/views/<业务域>/...`，组件放 `src/components/` 或 `views/**/components/`，API 放 `src/api/<业务域>/`，路由模块放 `src/router/routes/modules/*.ts`。
- [ ] **入口自愈**：`src/main.ts` 已有 `vite:preloadError` + `router.onError` 自动刷新机制（部署会清理旧 hash chunk），新增代码**不得破坏**该逻辑。
- [ ] **主题与样式**：Less 全局变量注入、AntDV `ConfigProvider` 配置符合项目现状（`colorPrimary` 绑定、暗黑模式算法）。

### 3.2 路由与权限
- [ ] **路由模块格式**：使用 `AppRoute` 类型，强制 `name`、`meta`（含 `title`、`icon`、`orderNo` 等）。懒加载用 `() => import('@/views/...')`。
- [ ] **路由注册**：模块导出 `default`（对象或数组），由 `routes/index.ts` 自动收集到 `basicRoutes/asyncRoutes`。
- [ ] **动态菜单**：侧边栏优先走后端 `sys_menu`（`sysMenuHelper.transformSysMenusToMenus`），空列表时降级静态菜单。新增菜单时需同步后端菜单配置（如涉及权限点）。
- [ ] **守卫**：沿用 `permissionGuard` 流程（token 校验、用户信息加载、路由构建、404 兜底），**不要**随意修改白名单或跳转逻辑。
- [ ] **路由命名**：`name` 使用 PascalCase（如 `BizCustomerList`），与页面组件命名保持一致。

### 3.3 API 层
- [ ] **Axios 封装**：统一使用 `@/utils/axios`：**请求头使用 `token` 而非 `Authorization`**、携带 `X-Tenant-Id`。
- [ ] **成功码判定**：响应成功码包含 `0/1/2/200`（项目现状），调用方需按此约定处理。
- [ ] **接口组织**：按业务域拆分，方法命名 `get/add/update/delete/...`，使用 `params/data` 正确区分 GET/POST。
- [ ] **前缀**：部分接口用 `/api/...`，系统接口用 `/system/...`，需与代理配置保持一致。

### 3.4 视图（CRUD）与字段配置驱动
- [ ] **CRUD 骨架**：搜索区、分页、表格、增删改弹窗、详情弹窗。编辑时优先调**详情接口**回填。
- [ ] **字段配置化**：表单字段较多时优先使用 `sections.ts` + `FieldItem.vue` + `MatrixTable.vue`。
- [ ] **点路径支持**：嵌套对象（`company.name`、`profile.dynamicInfo`）配合 `FieldItem` 路径解析。
- [ ] **多选/逗号分隔**：提交前 `join(',')`，回填时 `split(',').filter(Boolean)`。
- [ ] **级联（cascader）**：使用 `getIndustryTypeTree()/getPlanTypeTree()` 加载树形，FieldItem 仅回写末级值并反显完整路径。
- [ ] **弹窗**：优先用 `BizFullscreenModal.vue`（全屏切换、`scrolling`）。
- [ ] **状态切换**：行内状态变更需处理失败回滚或提示。
- [ ] **校验**：AntDV 表单校验规则清晰，必填项有 `trigger`。

### 3.5 组件、类型、编码风格
- [ ] **组件命名**：SFC 用 PascalCase，路由 `name` 用 PascalCase。
- [ ] **TS 类型**：接口 PascalCase，Props/Emits 使用泛型。跨域复用类型放 `types/` 或业务域内复用。
- [ ] **hooks 优先**：新逻辑优先用 `@/hooks/` Composables。
- [ ] **样式**：Less + `scoped`，避免硬编码色值。
- [ ] **调试痕迹**：移除临时 `console.log/debugger`。

### 3.6 构建与部署意识
- [ ] **类型检查**：`build` 含 `vue-tsc --noEmit`，提交前类型无错误。
- [ ] **Chunk 缓存**：知晓部署会清理旧 hash chunk，且已内置自动刷新兜底。新增懒加载路由时**不要**破坏该逻辑。
- [ ] **环境变量**：生产/开发用 `.env*` 正确区分。

## 4. 移动端（uniapp）开发核对

> 规范：`01-移动端(uniapp)开发规范.md`

### 4.1 工程结构
- [ ] **目录规范**：页面 `pages/<module>/<name>.vue`，分包 `packages/<module>/<name>.vue`，组件 `components/`，API `api/`，配置驱动 `config/*-sections.ts`。
- [ ] **pages.json**：`tabBar` 条件编译（仅 `#ifndef APP-PLUS` 且 `custom: true`），`easycom` 映射正确（`^w-(.*)` 要求目录+同名文件）。
- [ ] **入口**：理解 H5（`data-theme`）与非 H5（`v-bind(themeInlineVars)`）双轨主题注入差异。

### 4.2 页面与组件
- [ ] **SFC 风格**：`<script setup lang="ts">`，按 uni-app 生命周期使用。
- [ ] **自定义 tabbar**：统一采用 `PremiumBottomNav.vue`。

- [ ] **页面状态**：空态用 `empty-state`，加载状态用 `page-status`。

### 4.3 主题、样式、单位
- [ ] **主题变量**：优先用 `var(--color-*)`，**不要**引用空文件 `var.css`（实际变量在 `themes.scss` + `variables.scss`）。

### 4.4 网络请求与状态
- [ ] **请求封装**：统一用 `@/utils/request`，不要直接 `uni.request`。
- [ ] **token 超时**：走 `handleTokenTimeout` 流程。
- [ ] **Python 接口**：`/python/*` 前缀不追加 `api` 前缀。
- [ ] **状态管理**：Pinia stores 按既有模块组织，`useXxxStore` 命名。
- [ ] **防重复点击**：异步操作可用 `useLockFn`。

### 4.5 构建与运行

- [ ] **开发端口**：H5 开发端口 `8991`。
