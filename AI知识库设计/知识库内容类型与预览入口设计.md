# 知识库内容类型与预览入口设计

## 1. 背景
需求：知识库内容一个是“富文本编辑”、一个是“文件上传”，界面需要根据类型是访问富文本还是直接根据上传文件打开。

## 2. 现状梳理

| 概念 | 表 | 字段 | 说明 |
|---|---|---|---|
| 富文本/Markdown（编辑器创建） | `kb_document` | `content`（LONGTEXT）、`contentType`（richtext/markdown） | 现有已支持。由文档管理新增时保存。 |
| 文件上传（HTML/MD） | `kb_uploaded_file` | `fileContent`, `filePath`, `fileExt`, `document_id`, `parse_status` | 独立表。上传后自动解析生成 `kb_document`，建立 `kb_uploaded_file.document_id = kb_document.id`。 |
| 文件上传（PDF，新增） | `kb_uploaded_file` | 同上，扩展 `fileExt=pdf` | 见 PDF 支持设计。 |

## 3. 分支原则（“按类型决定入口”）

当用户“查看”文档时，需判断：该文档是**纯编辑器创建的文档**还是**由文件上传导入而来**。

**判断优先级（推荐）：**
1. 查找是否存在 `kb_uploaded_file` 且 `document_id = 当前文档id` 且 `del_flag=0`。  
   - 若存在，且 `fileExt` 为 `html/htm/md/markdown/pdf` → **优先走“文件预览页”（file-preview）**，以原始文件方式渲染（HTML 原样、PDF 原文件）
   - 若不存在 → 走**文档详情页（富文本/Markdown 渲染）**

**理由：**
- 文件上传导入的 HTML 原始源码含内联样式/结构，直接用原始文件预览更接近上传时的效果
- PDF 必须走文件预览（web-view/PDF.js）
- 纯富文本编辑器创建的文档走现有文档详情体验（wangEditor 渲染）

## 4. 后端支持（附带上传文件信息）

建议扩展 `KbDocument` 返回视图，或新增 DTO `KbDocumentDetailVo`，返回时附带关联上传文件：

```java
@Data
public class KbDocumentDetailVo extends KbDocument {
  private Long uploadedFileId;
  private String fileExt;
  private String filePath;
  private String originalName;
  private Boolean hasUploadedFile;
}
```

**Controller 调整：**  
`GET /api/knowledge/document/{id}` 返回 `AjaxResult<KbDocumentDetailVo>`。  
实现方式：根据 `document_id` 查询 `kb_uploaded_file`（取第一条有效记录）。

> 若暂不改后端返回结构，前端也可并行调用 `GET /api/knowledge/file/page?documentId={id}` 判断是否有关联记录。

## 5. 前端入口分支逻辑

### 5.1 know-vue（管理端）

**文档列表页（`views/knowledge/document/index.vue`）— 操作“查看”按钮：**
```js
function handleView(record) {
  // 判断是否由文件上传导入
  const hasFile = record.uploadedFileId || record.fileExt
  if (hasFile) {
    // 跳转文件预览（管理端也可复用文件预览逻辑，或直接打开弹窗）
    // 推荐：新开路由或弹窗 FilePreviewModal（支持 pdf/html/md）
    openFilePreview(record.uploadedFileId, record.id, record.fileExt)
  } else {
    // 跳转文档详情页（富文本渲染）
    goToDocumentDetail(record.id)
  }
}
```

**文件预览弹窗（增强版 `FilePreviewModal.vue`）：**
- 支持 `html/htm`：iframe srcdoc
- 支持 `md/markdown`：marked.parse + v-html
- 支持 `pdf`：iframe + PDF.js（推荐）或直接 `iframe src="/uploads/xxx.pdf"`

PDF.js 使用方式（示例）：
```html
<iframe v-if="isPdf" :src="pdfViewerUrl" style="width:100%;height:700px;border:none" />
```
`pdfViewerUrl = '/pdfjs/web/viewer.html?file=' + encodeURIComponent(pdfUrl)`

> 需将 PDF.js 静态资源放入 `know-vue/public/pdfjs/` 或按项目静态资源约定处理。

### 5.2 know-uniapp（移动端）

**文档列表页（`pages/knowledge/list.vue` 或 `document` 相关页）— “查看”入口：**
同上逻辑。  
跳转目标：
```js
if (hasFile && (ext==='pdf'||ext==='html'||ext==='htm'||ext==='md'||ext==='markdown')) {
  uni.navigateTo({
    url: `/pages/knowledge/file-preview/index?id=${uploadedFileId}&documentId=${id}&ext=${ext}`
  })
} else {
  uni.navigateTo({
    url: `/pages/knowledge/document-view/index?id=${id}`
  })
}
```

**文件预览页（`file-preview/index.vue`）扩展：**
- 已有：HTML（H5 iframe srcdoc；App web-view；小程序 rich-text 抽取 body）、MD（marked + rich-text）
- **新增 PDF 分支：**
  ```vue
  <!-- #ifdef H5 -->
  <iframe v-if="isPdf" :src="pdfUrl" class="pdf-frame" />
  <!-- #endif -->
  <!-- #ifdef APP-PLUS -->
  <web-view v-if="isPdf" :src="pdfUrl" />
  <!-- #endif -->
  <!-- #ifdef MP-WEIXIN -->
  <view v-if="isPdf" class="pdf-tip">
    <text>小程序暂不支持内预览 PDF</text>
    <button @click="openPdf">用外部应用打开</button>
  </view>
  <!-- #endif -->
  ```
- `isPdf = fileExt==='pdf'`
- `pdfUrl`：优先用 `filePath` 的可访问 URL（`appConfig.baseUrl + file.filePath.replace(/^\.\/?/, '')`）

## 6. UI 呈现建议
- 列表页“文件类型”列：增加 `PDF` 标签（红色或灰色区分）
- 文件管理页（know-vue `views/knowledge/file/index.vue`）已区分 html/md，新增 pdf 标签
- 预览页标题：显示原始文件名

## 7. 验证要点
- 富文本编辑创建的文档 → 走文档详情页（不走文件预览）
- 文件上传（HTML/MD）导入的文档 → 优先走文件预览页
- 文件上传（PDF）导入的文档 → 走文件预览页，能正常渲染 PDF
- 列表“查看”按钮能正确分支
- 后端返回附带上传文件信息时，前端能正确识别
