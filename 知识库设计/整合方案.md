## 四、整合策略

### 4.1 数据库整合方案

#### 策略：共存 + 迁移

```
现有表 (保留)                    V2表 (新增)
├── la_article                   ├── knowledge_base
├── la_article_cate              ├── knowledge_base_member
├── la_article_collect           ├── directory
├── la_comment                   ├── document
                                ├── memo
                                └── document_comment
```

**执行步骤:**

1. **创建新表** - 执行V2数据库设计SQL
2. **数据迁移** (可选) - 将现有文章迁移到document表
3. **菜单更新** - 添加知识库管理菜单

```sql
-- 迁移脚本 (可选)
-- 将la_article_cate迁移到knowledge_base
INSERT INTO knowledge_base (name, icon, description, visibility, doc_count, create_by, create_time, update_time)
SELECT name, '📚', CONCAT(name, '分类下的文章'), 1, 
       (SELECT COUNT(*) FROM la_article WHERE cid = la_article_cate.id AND delete_time IS NULL),
       1, create_time, update_time
FROM la_article_cate 
WHERE delete_time IS NULL;

-- 将la_article迁移到document
INSERT INTO document (knowledge_base_id, title, content, content_type, view_count, like_count, status, create_by, create_time, update_time)
SELECT 
       (SELECT id FROM knowledge_base WHERE name = (SELECT name FROM la_article_cate WHERE id = la_article.cid LIMIT 1)),
       title, content, 1, 
       click_virtual + click_actual, 0,
       CASE WHEN is_show = 1 THEN 1 ELSE 0 END,
       1, create_time, update_time
FROM la_article 
WHERE delete_time IS NULL;
```

## 五、字段映射关系

### 5.1 la_article → document

| 现有字段 | V2字段 | 转换逻辑 |
|----------|--------|----------|
| id | id | 新生成 |
| cid | knowledge_base_id | 通过la_article_cate.name匹配 |
| title | title | 直接映射 |
| desc | - | 不映射 (document无此字段) |
| abstract | - | 不映射 |
| image | - | 不映射 (document无此字段) |
| author | - | 不映射 (使用create_by) |
| content | content | 直接映射 |
| click_virtual + click_actual | view_count | 求和 |
| is_show | status | 1→1, 0→0 |
| sort | sort | 直接映射 |
| create_time | create_time | 直接映射 |
| update_time | update_time | 直接映射 |

### 5.2 la_article_cate → knowledge_base

| 现有字段 | V2字段 | 转换逻辑 |
|----------|--------|----------|
| id | id | 新生成 |
| name | name | 直接映射 |
| sort | sort | 直接映射 |
| is_show | status | 1→1, 0→0 |
| - | icon | 默认 '📚' |
| - | visibility | 默认 1 (公开) |
| - | doc_count | 统计对应文章数 |

### 5.3 la_comment → document_comment

| 现有字段 | V2字段 | 转换逻辑 |
|----------|--------|----------|
| id | id | 新生成 |
| article_id | document_id | 通过迁移映射 |
| user_id | user_id | 直接映射 |
| user_content | content | 直接映射 |
| parent_id | parent_id | 直接映射 |
| create_time | create_time | 直接映射 |

## 七、风险点

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 数据迁移失败 | 现有数据丢失 | 先备份，分批迁移，验证后删除旧数据 |

| 编辑器兼容性 | 文档编辑异常 | 使用uni-app官方editor组件，多端测试 |

## 八、技术决策

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 数据库策略 | 共存 + 迁移 | 保留现有表，新增V2表，避免破坏现有功能 |
| API路径前缀 | `/api/*` | 与现有 `/article/*` 路径分离，避免冲突 |
| 前端页面策略 | 新增目录 | 不修改现有news/news_detail页面，新增knowledge/document/memo目录 |
| 编辑器方案 | uni-app editor + Quill | 官方支持，跨端兼容，与know-uniapp技术栈一致 |
| 时间戳格式 | bigint (毫秒) | 与现有plan表一致，解决la_comment的datetime不一致问题 |
| 软删除 | delete_time | 与现有表一致 |
| 管理后台CRUD | 复用现有模式 | 参考know-vue的system模块开发模式 |
